25OLED Display

After Christmas, a gift: a screen! The tiny 0.96″ OLED shows text and graphics, and it introduces I2C — a two-wire bus that dozens of sensors share. We'll draw a Christmas tree in falling snow, then plot live sensor data.

🧰You need

  • Pico W + breadboard
  • 0.96″ SSD1306 OLED, 128×64, I2C (4 pins)
  • KY-018 Photoresistor (for the exercise)
  • 7 jumper wires

🔍I2C in a nutshell

I2C ("I-squared-C") uses two wires: SDA (data) and SCL (clock). The Pico is the controller; each device on the bus has a 7-bit address and only answers when called by it. Because every device has its own address, many can hang on the same two wires — tomorrow we'll add a second one. The Pico has two I2C controllers; we use I2C0 on GP4 (SDA) and GP5 (SCL).

The OLED (organic LED) has 128 × 64 pixels that each glow by themselves, so there's no backlight: black is truly black and it's readable at any angle.

🔌Wiring

Some OLED boards have VCC GND SCL SDA instead of GND VCC SCL SDA. Swapping power and ground can kill the display — check the labels printed on yours!

📓Code, step by step

1. Who's on the bus?

scan() calls every possible address and lists the ones that answer.

0x3c is the usual OLED address (some use 0x3d). Empty list? Check SDA/SCL aren't swapped and that VCC/GND are right.

2. Install the driver

The SSD1306 driver isn't built into MicroPython, but it's one small file from the official library. Easiest way: in Thonny choose Tools → Manage packages, search for ssd1306 and install it. Alternatively, once your Pico is on Wi-Fi (Day 24):

3. Hello, screen

Drawing happens in a hidden copy of the screen in memory (a frame buffer). Nothing appears until you call show(), which sends the whole buffer over I2C. The built-in font is 8 × 8 pixels: 16 characters per line, 8 lines.

Coordinates start at the top-left corner (0, 0); x grows to the right (0–127), y grows downwards (0–63). Many of these displays are two-colour: the top 16 rows glow yellow, the rest blue — that's fixed in the hardware.

4. Draw a Christmas tree

A triangle is a stack of horizontal lines that get wider. Three stacked triangles plus a trunk make a tree; a few pixels make the star.

5. Let it snow

Each snowflake is a small list [x, y, speed]. Every frame we clear the screen, redraw the tree, move each flake down and draw it. Flakes that fall off the bottom restart at the top. The tiny x wobble makes them drift.

🧠What you learned

  • The I2C bus: SDA, SCL, addresses, scan().
  • Installing a driver with Thonny or mip.
  • Frame buffers and the drawing API: text, pixel, hline, line, rect, fill_rect, show.
  • Simple animation: clear, update, draw, show, repeat.

⭐Exercise: a scrolling light graph

Remember Day 8's photoresistor? Turn the OLED into an oscilloscope-style plotter for it:

  1. The top 16 rows show the current value as a number and a percentage, e.g. Light 73%.
  2. The area below (rows 16–63) is a graph: every 100 ms, shift it one pixel to the left and draw the newest value as a vertical line at the right edge.
  3. Draw a dotted line at the average of everything currently on the graph.
Hint

Keep a list of the last 128 values; redraw the graph from the list each frame (that's simpler than scrolling pixels). Map a value 0…1 to a y position with y = 63 - int(v * 47).

Show solution

Redrawing everything from a list each frame keeps the code simple and makes extras like the average line easy. 128 columns × a few drawing calls is fast enough for 10 frames per second.

The dotted average line is drawn in black where it crosses the filled graph and in white above it, so it's visible either way.
