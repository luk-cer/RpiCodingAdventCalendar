16Candy-Cane Barcodes

The line-tracking sensor that steers robots along black tape can also read stripes. Today you'll swipe it over printed stripes, measure each one — and in the exercise decode your own secret barcode, beep and all.

🧰You need

  • Pico W + breadboard
  • KY-033 Line tracking sensor
  • KY-006 Passive buzzer
  • Printed stripes (below) or a black marker and paper
  • 6 jumper wires

🔍How it sees black

The KY-033 shines infrared light down and measures how much comes back. White paper reflects a lot; black ink absorbs it. A comparator turns that into a digital signal, and the potentiometer sets where "black" starts. It works best 2–10 mm above the paper.

🔌Wiring

Use longer jumper wires (or female-to-male wires) for the KY-033 so you can move it over the paper while the rest stays on the breadboard.

🖨️Print this

Print this page (or draw it with a thick marker). The stripes encode a letter: thin bar = 0, thick bar = 1. You'll decode it in the exercise.

📓Code, step by step

1. Black or white?

Hold the sensor over white paper, then over a black bar. Adjust the potentiometer until the board LED reliably switches between the two. We'll store the white level at start-up, like on previous days:

2. A scanner beep

3. Recording edges

To measure stripes we need the exact moments the signal changes. An interrupt stores each change as (time in µs, is_black).

4. From edges to bar widths

A black bar starts at a "became black" edge and ends at the next "became white" edge. Their difference is how long the bar was under the sensor. A swipe is finished when nothing has happened for half a second.

5. Scan!

Swipe steadily across the printed stripes. Each scan prints how many bars were found and their widths in milliseconds. Notice the thick bars come out roughly 2.5× wider — if your swipe speed was even.

🧠What you learned

  • Reflective IR sensors and adjusting comparator thresholds.
  • Recording timestamps of edges, then post-processing them into widths.
  • Detecting "end of input" with a timeout.

⭐Exercise: decode the secret letter

  1. A valid code has exactly 8 bars. Each thick bar is a 1, each thin bar a 0, first bar = most significant bit.
  2. Since swipe speed varies, don't use a fixed width. Use the midpoint between the narrowest and widest bar as the threshold.
  3. Turn the 8 bits into a number and the number into a character with chr(). Print it and play a happy two-tone beep. Wrong number of bars → low error buzz.
  4. Bonus: make your own barcode for your initial. (ord("L") gives its number; "{:08b}".format(76) its bits.)
Hint

Build the number bit by bit: value = value * 2 + bit (or value = (value << 1) | bit). What happens if all 8 bars are the same width? Think about that edge case.

Show solution

The relative threshold makes the decoder tolerant to how fast you swipe. If every bar is about the same width, the code can't contain both 0s and 1s, so we reject it (that would be 0x00 or 0xFF, which aren't letters anyway).

The printed code is 01000001 = 65 = "A". Swiping right-to-left reverses the bits — can you detect and correct that automatically? (Hint: add a start marker, like real barcodes do.)
