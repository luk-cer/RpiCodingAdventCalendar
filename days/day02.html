Pico W Coding Advent Calendar · Day 2

2Press the Button

Yesterday the Pico only talked. Today it listens: a push button turns yesterday's traffic light into a pedestrian crossing. You'll meet inputs, edge detection and the infamous button "bounce".

🧰You need

  • Pico W + breadboard
  • KY-004 Button module
  • LED Traffic Light module
  • 8 jumper wires

🔌Wiring

The traffic light is wired exactly like Day 1. The button module needs three connections: + to 3.3 V, − to ground and S (signal) to GP16. The module contains a 10 kΩ resistor that holds the signal at a fixed level while the button is not pressed; pressing it pulls the signal to the opposite level.

Two new things in this diagram: the red wire brings 3.3 V from the Pico's 3V3 pin to the top + rail, and a red "bridge" wire on the far right connects the top rail to the bottom one. From now on, any module can grab power from the nearest rail.

📓Code, step by step

1. Read the button

Pin.IN makes GP16 an input. value() now measures the voltage: above about 2 V reads as 1, below about 0.8 V as 0. Run this, then press and hold the button and run it again.

2. Watch it live

A loop that prints 10 times a second lets you see the value change as you press. Stop it with the Stop button.

On most KY-004 boards you'll see 1 when released and 0 when pressed (the resistor "pulls up", the button connects to ground). Some batches are wired the other way round. Instead of guessing, our program will simply remember the idle value at start-up: anything different means "pressed".

3. Count presses — and discover bouncing

We want to react to the moment the button goes down (an edge), not to it being down. So we compare the current state with the previous one.

Press slowly ten times. You'll probably see the counter jump by 2 or 3 sometimes! Mechanical contacts physically bounce for a few milliseconds, producing several tiny presses. The cure is debouncing: after an edge, ignore everything for a short time.

time.ticks_ms() is a millisecond clock that keeps running. Always subtract two ticks values with time.ticks_diff(new, old) — it handles the moment the counter wraps around.

4. The pedestrian crossing

The traffic light now stays green for cars until someone presses the button. Then it runs one stop-cycle and goes back to green. While the light is red, the on-board LED blinks as the "walk" signal.

The main loop just waits for a press. We add a minimum green time so one impatient person can't stop traffic forever.

🧠What you learned

  • Pin(n, Pin.IN) and .value() read a digital input.
  • A pull-up/pull-down resistor gives an input a defined idle level.
  • Edge detection (compare with the previous state) and debouncing (ignore changes for ~50 ms).
  • time.ticks_ms() + time.ticks_diff() measure time without blocking.

⭐Exercise: short press, long press, night mode

  1. Measure how long the button is held. A short press (under 1 second) requests the crossing as before.
  2. A long press (1 second or more) toggles night mode: the yellow light blinks every 0.5 s and short presses are ignored. Another long press returns to normal green.
  3. The blinking must not freeze the program — the button must still work while yellow blinks. That means no time.sleep(0.5) for blinking!
Hint

Write a function read_press() that returns None, "short" or "long": when it sees the button down, it waits until release and measures the duration with ticks_ms. For non-blocking blinking, remember when you last toggled and toggle again when 500 ms have passed.

Show solution

read_press() classifies a whole press after release; presses shorter than 30 ms are treated as bounce and ignored. The main loop runs every 10 ms and does a little bit of work each time (check the button, maybe toggle yellow) — this "never block" style is how almost all embedded programs are structured.

One limitation: read_press() only answers after you let go, so a long press doesn't switch modes until release. Can you change it so night mode switches the moment the 1-second mark is reached?
