Pico W Coding Advent Calendar · Day 8

8Night Light

So far every input was just 0 or 1. Today the Pico measures how much: a light-dependent resistor tells it how bright the room is, and the RGB LED from Day 4 becomes a cosy night light that fades in as it gets dark.

🧰You need

  • Pico W + breadboard
  • KY-018 Photoresistor (LDR)
  • KY-016 RGB LED (from Day 4)
  • 8 jumper wires

🔍How the LDR works

A light-dependent resistor has high resistance in the dark (around 1 MΩ) and low resistance in bright light (a few kΩ). The module puts it in series with a fixed 10 kΩ resistor — a voltage divider. The voltage in the middle, on pin S, moves between 0 and 3.3 V as the light changes. We measure that voltage with the Pico's ADC (analog-to-digital converter) on GP26.

🔌Wiring

📓Code, step by step

1. Your first analog reading

ADC(26) reads GP26. read_u16() returns 0 for 0 V up to 65535 for 3.3 V. (The Pico's ADC really has 12 bits = 4096 steps; MicroPython scales it up to 16 bits so all boards look the same.)

2. Watch it in the plotter

Turn on View → Plotter in Thonny and run this. Cover the sensor with your hand, then shine a phone torch on it.

3. Smoothing out the noise

The plot is a bit jittery — electrical noise and flickering room lights. Two cures: average several readings, and blend each new value into a running average (an exponential moving average). ALPHA = 0.1 means "trust the new reading 10 %".

4. Map darkness to brightness

Your room has its own range: maybe darkness goes from 0.15 (lamp on) to 0.7 (hand over sensor). We map that range onto LED brightness 0…1 and clamp values outside it. Try the readings from your plot for BRIGHT_ROOM and DARK_ROOM.

5. The night light

A warm candle colour (lots of red, some green, a little blue), scaled by how dark it is.

🧠What you learned

  • Voltage dividers turn a changing resistance into a changing voltage.
  • ADC(26).read_u16(); only GP26, GP27, GP28 are analog inputs.
  • Averaging and exponential smoothing; mapping and clamping ranges.

⭐Exercise: self-calibrating light with a logbook

  1. Hard-coded BRIGHT_ROOM/DARK_ROOM values break when you move the Pico to another room. Make the program learn them: remember the smallest and largest darkness ever seen and map between those. Ignore the first second so the start-up value doesn't fix the range.
  2. Add hysteresis: the light switches on only when the level goes above 0.6 and off only when it drops below 0.4. In between it keeps its previous state (no flickering at dusk).
  3. Every 10 seconds, append a line seconds,darkness,light_on to a file light_log.csv on the Pico. Open it in Thonny afterwards (View → Files).
Hint

lo = min(lo, smooth) and hi = max(hi, smooth). Guard against hi - lo being tiny (division by almost zero) — require at least 0.05 difference before mapping. For the file: with open("light_log.csv", "a") as f: f.write(...).

Show solution

The program now has state (lo, hi, is_on) that it updates over time. Writing to flash with "a" (append) mode adds lines to the end; we log only every 10 s because flash memory wears out if written constantly.
